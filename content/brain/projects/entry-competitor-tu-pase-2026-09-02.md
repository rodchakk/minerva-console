Competitor intelligence captured from operator screenshots and public Tu Pase / CODES web presence reviewed on 2026-09-02.

- Product: **Tu Pase**.
- Public developer/company identity observed: **CODES — Compañía de Soluciones de Software S.A. de C.V.**, Honduras.
- Operator screenshot showed the Android resident app as **`Tu Pase - Residentes`**.

This places Tu Pase in the **high-relevance direct competitor** category for ENTRY.

## Product architecture signal — one platform, multiple communities

One of the most important findings is that Tu Pase publicly describes a **multi-organization SaaS model**: multiple residential communities can operate on the same platform while keeping their own environment/users/permissions.

Strategic implication for ENTRY:

> This independently supports the current Minerva preference that **ENTRY remains one platform/product with community-level identity and configuration**, rather than creating a separate native app for every residential project.

Do **not** treat this as proof that ENTRY should copy Tu Pase's architecture implementation details. It is useful market confirmation that a single-platform / multi-community model is commercially understandable in Honduras.

## Buyer/channel signal — beyond patronatos

Public Tu Pase terms/materials indicate the platform can be contracted/used in contexts that include:

- residential communities / condominiums;
- real-estate/property administrators;
- security companies / operators.

This matters because it reinforces the research already opened from Guardian X:

> There may be a meaningful buyer **above the individual community level** — an administrator, developer/operator or security company that influences several residential communities.

Tu Pase + Guardian X now provide **two separate competitor signals** pointing toward a multi-community/admin channel.

This still does **not** prove market size, buyer concentration, procurement authority or willingness to switch providers. Those remain research questions.

Public Tu Pase materials reviewed on 2026-09-02 include claims/positioning around:

- implementation in approximately **5 days**;
- training included;
- ongoing support;
- no forced permanence / long-term lock-in language;

Pricing was not found as a simple public list-price table comparable to Guardian X.

Commercial implication:

- ENTRY should not answer this by immediately adding every adjacent module.
- ENTRY should preserve its clearest wedge: **authorization → validation → access record → administrative visibility**, then expand only where repeated buyer evidence supports it.

## Multi-Residential / Admin Channel research — strengthened

Existing near-term research remains active:

> **Multi-Residential / Admin Channel — research pending, near term.**

Tu Pase strengthens the case for executing this research because two competitors now publicly signal multi-community/admin use cases.

Add the following questions to that research:

1. Which Honduras/SPS property-management or residential-administration companies currently use Tu Pase, Guardian X or another multi-community platform?
2. Do security companies bundle access software as part of their service contract?
3. When an administrator manages several communities, who signs the software contract: administrator, patronato, developer or security provider?
4. Is centralized portfolio visibility actually used operationally, or mainly marketed as a convenience?
5. Which actions must remain isolated per community vs centralized across the portfolio?
6. Are residents comfortable using one shared platform brand across many communities?
7. How do competitors handle onboarding/offboarding when a community changes administrator or when a developer hands control to a patronato?
8. Does one administrator relationship realistically produce multiple deployments, or does each patronato still approve independently?

## Decision rule

Do **not** add finance, SOS, guard rounds, multi-residential dashboards or other modules merely because Tu Pase offers them.

Promote any adjacent capability only when field/research evidence shows:

1. the problem is repeated across real target buyers;
2. ENTRY has a credible advantage or necessary parity requirement;
3. the buyer will pay for it or it materially improves conversion/retention;
4. technical/support complexity is justified;
5. it does not distract from landing the first strong reference customers.
